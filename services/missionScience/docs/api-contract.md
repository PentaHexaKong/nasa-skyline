# API contract

The request schemaVersion is 1.0. EvaluationRequest and EvaluationResponse are the implemented Pydantic schemas. Generated JSON Schemas and OpenAPI are delivered in this directory.

GET /health reports process liveness and asset-directory presence. GET /v1/capabilities declares request restrictions. GET /v1/sites lists verified catalog coordinates. GET /v1/scientific-profiles declares ephemeris semantics. POST /v1/evaluate accepts an EvaluationRequest. POST /v1/compare accepts evaluations as a list of requests under one object. POST /v1/optimize accepts candidates and delaysDays.

Evaluate returns schemaVersion, dataState, result, error and provenance. Computed result contains site, timesS, Sun/Earth tracks, intervals, event times, maximum uninterrupted visibility, maximum outages, terrain skyline and mission-constraint violations. Times and intervals are seconds relative to the requested UTC epoch. visibleFraction is derived from refined detected intervals and remains subject to missed-event warnings. Solar visibleDiskFraction is a track quantity distinct from the duration fraction for the selected solarDefinition.

Validation failures return HTTP 422. Oversized bodies return 413. Busy admission returns 503. Scientific missing data and unsupported physical cases return a structured unavailable evaluation. Each request admits at most 6000 time intervals and at most 365 days, so fine cadence limits the supported duration. Body limits are 1 MiB. Compare and optimize require common physical definitions. Long workloads exceeding the declared synchronous bounds are rejected. There is no background job queue.

configs/exampleRequest.json and experiments/exampleResponse.json are actual schema-conforming examples generated by the real evaluation runner.
